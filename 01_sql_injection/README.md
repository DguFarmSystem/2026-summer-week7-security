# SQL Injection 로그인 우회 실습 (약 30분)

슬라이드 28 "SQL Injection"의 위험한 방식 / 안전한 방식 코드를 실제로 동작하는 로그인
페이지로 만든 것입니다. 문자열을 그대로 이어붙인 쿼리가 어떻게 뚫리는지 직접 보고,
파라미터 바인딩으로 막는 것까지 한 번에 체험합니다.

## 준비 (2분)

```bash
cd 01_sql_injection
pip install -r requirements.txt
python app.py
```

브라우저에서 http://127.0.0.1:5001 접속. 터미널에는 실행되는 쿼리가 그대로 찍힙니다.

## 진행 순서

### 1. 정상 로그인 먼저 (3분)
`alice` / `alice1234` 로 로그인해서 정상적으로 동작하는 것을 확인합니다.

### 2. 공격 — 학생 스스로 풀어보기 (8분)
**app.py를 보여주지 말고**, 로그인 페이지 URL만 주고 "admin으로 로그인해보라"고
과제를 냅니다. 막히면 순서대로 힌트를 줍니다. (페이지 소스보기를 하면 힌트가
HTML 주석으로 이미 숨어있습니다 — webhacking.kr 식입니다.)

<details>
<summary>힌트 1 (막 시작했을 때)</summary>

이 로그인은 서버에서 아이디/비밀번호로 SQL 쿼리를 만들어 확인합니다.
아이디 칸에 평범한 글자 말고 **특수문자**를 넣어보면 어떤 반응이 오는지 보세요.
</details>

<details>
<summary>힌트 2 (5분 넘게 못 풀 때)</summary>

아이디에 작은따옴표(`'`) 하나만 넣고 로그인해보세요. 터미널에 찍히는 쿼리를
같이 보면, 내 입력이 SQL 문법의 일부로 취급된다는 걸 알 수 있습니다.
</details>

<details>
<summary>힌트 3 (그래도 못 풀 때)</summary>

SQL에서 `--` 뒤는 전부 주석 처리됩니다. 비밀번호를 검사하는 부분 자체를
통째로 주석으로 날려버릴 수 있다면, 비밀번호를 몰라도 통과할 수 있습니다.
</details>

<details>
<summary>정답 (최후의 수단)</summary>

- 아이디: `admin' --`
- 비밀번호: 아무 값이나

또는

- 아이디: `' OR '1'='1`
- 비밀번호: `' OR '1'='1`
</details>

### 3. 왜 뚫리는지 다 같이 정리 (5분)
터미널에 찍힌 실제 쿼리를 보여주며, 슬라이드 28의 "공격이 막히는 이유"와 연결합니다.
**입력값을 문자열로 이어붙였기 때문에** 공격자가 SQL 문법 자체를 조작할 수 있었다는 점을
짚습니다.

### 4. 패치 (10분)
이제 `app.py`를 같이 열어봅니다. 상단의 `SECURE_MODE = False` 를 `True` 로 바꾸고
서버를 재시작합니다.

```bash
python app.py
```

같은 공격 입력을 다시 시도 → 이번엔 로그인 실패하는 것을 확인합니다.
파라미터 바인딩(`?`)을 쓰면 입력값이 SQL 문법이 아니라 **값으로만** 취급된다는 점을
강조하며 마무리합니다.

---
실습이 끝나면 `SECURE_MODE`를 다시 `False`로 되돌려 두면 다음 반에서도 그대로 쓸 수 있습니다.
